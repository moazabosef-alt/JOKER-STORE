# متجر الجوكر — الموقع الإلكتروني

موقع مستقل عن تطبيق أندرويد، جاهز للنشر المجاني على GitHub Pages، ويستخدم **نفس قاعدة بيانات Supabase** الموجودة لدى تطبيق الجوكر.

## 1) إعداد Supabase

- افتح مشروع Supabase الذي تستخدمه مع التطبيق.
- من نافذة **Connect** أو **Project Settings → API Keys** انسخ **Publishable key** الذي يبدأ غالباً بـ `sb_publishable_`.
- افتح ملف `config.js` وضعه مكان `PASTE_YOUR_SUPABASE_PUBLISHABLE_KEY_HERE`.
- رابط المشروع موجود في `config.js`؛ راجعه مقابل عنوان المشروع داخل Supabase.
- **ممنوع** وضع مفتاح `service_role` أو `sb_secret_` في الموقع أو GitHub؛ الموقع عام ويمكن للزوار قراءة ملفاته.
- يجب أن تكون جداول `categories`, `products`, `orders`, `admin_users` وسياسات RLS والتخزين `product-images` معدّة في Supabase. إذا كان تطبيق أندرويد يستخدم هذه الجداول بالفعل، **لا تشغّل مخطط SQL مرة ثانية بلا مراجعة**.
- لتفعيل الإدارة، أنشئ مستخدم بريد إلكتروني في **Authentication → Users**، ثم أضف UUID الخاص به إلى جدول `public.admin_users` من SQL Editor:

```sql
insert into public.admin_users (user_id)
values ('ضع-معرف-المستخدم-UUID-هنا')
on conflict (user_id) do nothing;
```

## 2) رفع الموقع إلى GitHub

1. افتح github.com وسجّل الدخول.
2. اضغط علامة `+` ثم **New repository**.
3. سمِّه `al-joker-web`، واجعله **Public**، ثم **Create repository**.
4. اضغط **Add file → Upload files** وارفع **محتويات** هذا المجلد (وليس ملف ZIP). يجب أن تظهر الملفات `index.html`, `style.css`, `app.js`, `config.js` ومجلد `assets` في جذر المستودع.
5. اضغط **Commit changes**.
6. افتح **Settings → Pages**، واختر **Deploy from a branch**، ثم `main` و`/(root)`، واضغط **Save**.
7. انتظر حتى ينتهي النشر. سيكون الرابط عادة:
   `https://moazabosef-alt.github.io/al-joker-web/`

## 3) ماذا يتضمن الموقع؟

- واجهة عربية متجاوبة مع الهاتف والكمبيوتر وشعار متجر الجوكر.
- أقسام ومنتجات وصور وأسعار وبحث وسلة مشتريات.
- إنشاء طلب داخل Supabase أو إرسال ملخص السلة عبر واتساب.
- تسجيل دخول الإدارة، إضافة/تعديل/حذف منتجات وأقسام، رفع صور، متابعة الطلبات وتغيير الحالة.
- لا حاجة لبناء APK أو إعداد GitHub Actions.

## 4) ملاحظات مهمة

- مفتاح Publishable مصمم للاستخدام في المتصفح، لكن الأمان يعتمد على **Row Level Security (RLS)** وسياسات التخزين؛ راجعها قبل مشاركة الرابط.
- الطلبات العامة تخضع للسياسات الحالية، وقد تتطلب حماية إضافية من الطلبات الوهمية أو الإغراق قبل الاستخدام التجاري الكبير.
- **السعر والإجمالي المحفوظان في الطلب يرسلهما المتصفح**؛ يجب التحقق منهما على الخادم قبل اعتبار الطلب معتمداً أو استخدامه للدفع. الموقع الحالي لتلقي طلبات أولية وليس بوابة دفع إلكتروني.
- لا يتضمن الموقع دفعاً إلكترونياً أو شحنًا آلياً أو رسائل واتساب تلقائية. إرسال واتساب يتم من خلال فتح محادثة يوافق عليها الزبون.
- الخطة المجانية في GitHub Pages وSupabase لها حدود، وقد تتغير شروطها.
- للموقع الجديد قاعدة الكود الخاصة به؛ لن تتغير ملفات مستودع تطبيق أندرويد `joker_complete_repo`.


## 5) الإعجابات والاقتراحات (إضافة جديدة)

1. قبل نشر التحديث، افتح Supabase → SQL Editor في مشروع المتجر نفسه.
2. انسخ ملف `SUPABASE_FEEDBACK.sql` وشغّله مرة واحدة. لا يحذف المنتجات أو الطلبات. **راجع السياسات الموجودة** إذا كنت شغّلت إعدادات مشابهة من قبل.
3. ضع Publishable key في `config.js`، ثم ارفع الملفات كلها إلى GitHub Pages.
4. افتح الموقع واضغط زر الإعجاب، وجرّب إرسال اقتراح. افتح إدارة المتجر ثم تبويب «الاقتراحات» لقراءتها.
5. العداد مشترك عبر Supabase ويستمر بعد تحديث الصفحة. لكل متصفح معرّف محلي يمنع الإعجاب المكرر من نفس المتصفح عادةً، **لكنه ليس نظاماً محكماً لمنع التلاعب**؛ يستطيع المستخدم حذف بيانات المتصفح أو استخدام جهاز آخر.
6. حماية إضافية قبل الإطلاق الواسع: أضف CAPTCHA وتحديد معدل الطلبات (rate limiting) عبر خدمة خادمية، لأن إدخال الاقتراحات متاح للعامة.
7. إذا ظهر خطأ في تبويب الاقتراحات، راجع سياسات `admin_users` الحالية لتجنب الاستدعاء الذاتي في RLS.
8. **تنبيه:** نسخة الموقع هذه ما زالت تستخدم تسجيل دخول الإدارة بالبريد وكلمة المرور، ولا تطبق بعد نظام أسماء المستخدمين والصلاحيات الفردية للموظفين العشرة. يلزم تنفيذ ذلك واختباره قبل منح الموظفين صلاحية الدخول.

## تحديث التصميم الفاخر
- ألوان أسود وأحمر وذهبي، وشعار الجوكر الأصلي داخل `assets/logo.png`.
- نصوص الإلكترونيات والأجهزة الإلكترونية باللون الأبيض على الخلفيات السوداء، مع عناوين ذهبية للتمييز.
- تحديث واجهة الصفحة الرئيسية وبطاقات المنتجات وتصميم الهاتف.
- **مهم:** ما زال تشغيل قاعدة البيانات يحتاج إلى إضافة Publishable key إلى `config.js` وتشغيل `SUPABASE_FEEDBACK.sql` للإعجابات والاقتراحات، ثم اختبار الوظائف بعد النشر. لا تضع أي مفتاح سري في GitHub.


## 6) تحديث قائمة VIP (نوفمبر 2026)

- أُضيف تسجيل VIP مجاني من واجهة المتجر مع إشعار واضح بالمزايا وسياسة الخصوصية وموافقة صريحة قبل إرسال البيانات.
- بيانات أعضاء VIP محفوظة في `joker_vip_members`، ولا يتيح RLS قراءتها إلا للمدير والموظفين الذين لديهم صلاحية `vip.view`.
- أُضيف تبويب «أعضاء VIP» للبحث عن الأعضاء ومراجعة بياناتهم وعدد الزيارات ورصيد النقاط. صلاحية `vip.points` تسمح بإضافة/خصم نقاط يدوياً مع تسجيل سبب العملية.
- سُجلت حركات النقاط في `joker_vip_points_ledger` كسجل تدقيق مستقل.
- تُسجّل المشتريات في سجل العضو بعد تحويل حالة الطلب إلى «تم التسليم» (`done`) فقط؛ الطلبات المرفوضة/غير المكتملة لا تُحتسب.
- الإحالة تُصبح مؤهلة بعد أول عملية شراء مكتملة للعضو المُحال. لم تُحدد مكافأة الإحالة بعد.
- **مهم:** لم يتم تحديد معدل اكتساب النقاط من قيمة المشتريات أو آلية استبدالها بعد؛ سجل النقاط جاهز، لكن الاحتساب الآلي للنقاط لن يبدأ حتى اعتماد سياسة النقاط من إدارة المتجر.
- قاعدة Supabase المرتبطة بالموقع تم تحديثها بالفعل في هذه الجلسة. لا تعِد تشغيل أي SQL عشوائياً على قاعدة البيانات.
- تم إلغاء الحد البرمجي البالغ 10 صور للواجهة، وأصبحت الصور تُحمّل على دفعات مرتبة.
- أصبحت أقسام المتجر ظاهرة مباشرة أسفل الواجهة المتحركة، مع روابط سريعة للأقسام والعروض والألعاب والإعجاب.
